# Corrected PRCC coverage rebuild

Open `/coverage.html` from the **Coverage** link and select or drop all corrected CSV/XLSX files. Transfers start immediately. Each uploaded file is durably queued and automatically imported and synchronized; no Start, approval, client confirmation or manual Google sync step is required. Keep the browser open until transfers finish; processing then runs sequentially on the local Node server without an open browser tab. Leave the server and computer running overnight. Failed files do not stop the remaining queue. Errors/review is optional and available later.

This update preserves all 386 existing coverage records (107 Conquest and 279 Orion) and all existing upload jobs. **Every client, including Conquest, synchronizes to Google. Do not run the reset command to install this update.** Restart the local server to load the new code. A separate persistent client-delivery queue automatically backfills the existing Coverage Library without uploading or parsing source files again. Completed upload jobs stay intact; their historical sync tags are retained as history only. The Coverage Library displays authoritative client delivery status, exact spreadsheet name/link, actual Drive parent-folder name/link, last verification time and verified record count. Status reads Idle before any jobs/data, Running during uploads or deliveries, and Completed when work is terminal (with failures visible).

Existing `coverage-v2.json` destination IDs are reused. The optional approved `coverageDestinations` map in `app-config.json` also supports canonical client names, saved aliases or client IDs as keys, with spreadsheet ID strings or `{ "spreadsheetId": "...", "tab": "Coverage" }` values. OAuth/config saves preserve these mappings. Missing/deleted destinations resolve to the existing dedicated client spreadsheet before creating another. No historical coverage is imported from Google.

## Titles and the five-tab client workbook

The structural/style reference was the supplied `Conquest - Media Coverage.xlsx`, found in Downloads. Only its headers, font choices, widths and presentation were inspected; no reference coverage rows or legacy Sheet1 were imported. The application embeds the sanitized template definition, so runtime operation does not require that file.

Every canonical client now uses `Media List Builder / Clients / [Client Name] / [Client Name]`. Known spreadsheet IDs are renamed and moved in place, preserving contents and explicit permissions. Folder IDs and spreadsheet IDs persist in coverage state. Folder lookup is scoped to the expected parent and reuses canonical matches. Unrelated files are never selected for migration. Existing Sheet1 is renamed to Coverage rather than copied; a populated extra tab is never silently deleted.

Exactly five standard tabs are maintained in order:

- Coverage: Date | Title | Client | Media Outlet | Reporter | Spokespersons ID | Coverage Type | Sentiment | Status | Reach | URL
- Reporters: Name | Outlet | Email
- Outlets: Outlet | Outlet Type | Monthly Reach / UVM
- Client Contact: Name | Title | Email | Phone
- Team Contact: Name | Title | Email | Phone

The theme and the entire grid of each tab use Calibri, including populated cells and empty template areas. Headers are bold/frozen, widths follow the reference where specified and otherwise are widened for readability, dates display as yyyy-mm-dd, and original URL cells have explicit clickable links and the reference's light yellow fill. Google read-back verifies the theme, all populated cells plus empty-grid samples, header styles, column widths, tab order and frozen rows. Theme updates preserve the complete existing theme color set.

Reporter rows deduplicate by name/outlet. Email addresses come only from unambiguous Active directory matches. Outlet rows deduplicate by name; reach comes from verified outlet metadata or the newest observed original PRCC reach. Missing outlet types remain blank; the importer's default classification is not treated as verified metadata. Client contacts are scoped to that client; unscoped team contacts may be shared. Contact writes append only unseen contacts and never replace existing manual rows or fill their blank fields automatically.

Orion's queued CSV uses `Coverage Link` for headlines, while Conquest uses `Status`. Titles now support explicit title/headline columns, descriptive link columns, hyperlink display text and headline-bearing Status cells. Generic statuses and raw URL strings are not titles. A one-time source-evidence repair reads only known queued uploads and matches existing records by canonical client and article URL, using saved tab/row provenance to resolve duplicate-URL headline variants. It changes only title/review fields, creates no records or jobs, and flags unrecoverable titles for later review. Template-version and title changes automatically schedule delivery to the same existing spreadsheet IDs.

## Optional reset reference (not part of normal operation or this update)

The live reset was **not executed** during development. Stop the application before resetting. From this repository in Command Prompt:

```bat
set "PATH=C:\Users\Sam\node-portable\node-v22.23.1-win-x64;%PATH%"
npm run coverage:fresh-start -- --confirm
npm run coverage:verify
npm start
```

Run `npm run coverage:verify` again after startup. It exits nonzero unless coverage, upload jobs, pending coverage synchronization jobs and coverage research entries are all zero, with legacy migrations disabled. Existing uploads will naturally make the check fail after you start importing.

The reset refuses to run without `--confirm`, inside Vercel, while the standalone server PID is active, against the project/root directory, or against linked data directories. It backs up the entire local data directory into a timestamped sibling `coverage-backup-*` directory before changing anything. Explicit external configuration/auth paths are also backed up. It then clears coverage and coverage-owned queue/cache/history files and keys, resets dedicated spreadsheet mappings, and creates a new empty generation. Reporter records, archived reporters, clients, contacts, reporter enrichment, settings and OAuth credentials are retained. Backups contain private data and must stay outside version control. No Google/Blob SDK is used by the reset.

## Import and sync behavior

- PRCC mapping: Press Type → Coverage Type; Date → Date; Publication → Media Outlet; UVM → Reach; Reporter → Reporter; Spokesperson → Spokespersons ID; Status → Title; Raw URL → URL. Explicit Title takes precedence. XLSX tabs and original row numbers are retained; blank rows do not shift error locations.
- Client names/aliases and explicit PRCC/PR Campaign/year filename conventions identify clients automatically. Exact saved identities take precedence; ambiguous matches and unreliable filenames fail with a needs-attention message. No client is guessed between competing saved identities, and other files continue.
- Missing or invalid HTTP/HTTPS URLs reject the row. Accepted original URLs are stored unchanged. Same canonical client and normalized URL deduplicate across files/restarts (hostname case, fragments and query parameter ordering normalize for identity only); different clients remain separate. Distinct article URLs are never merged by reporter/publication. Reach never supplies a title.
- Local imports commit before remote work. Retry uses deterministic range updates over the full client dataset, not append; it cannot duplicate rows. Five attempts for temporary errors use persisted exponential backoff timestamps while later files continue. Permanent Google errors fail that file. Retry failed resets the attempt budget without reimporting locally. Identical uploads of an already verified client dataset skip synchronization; after an interrupted write, batches already matching Google are verified without being rewritten. Pause/cancel take effect between files. Completed jobs stay completed.
- Google uses existing OAuth and approved destinations for **all clients**, falling back to a dedicated canonical-client spreadsheet inside its own client folder. Writes use batches of 500 rows, rate limiting and read-back verification. A lost create response is recovered by the generation/client app property. The configured folder and Clients/client hierarchy must exist or be creatable with the connected account; invalid locations fail clearly without creating files elsewhere. Stored Orion and other valid destination IDs are reused. The five standard tabs replace the prior single-tab delivery layout. Incompatible headers or populated extra tabs fail without discarding data. Master reporter/outlet destinations are rejected. No unrelated Drive files are renamed, moved or deleted.
- Local success and Google success have separate counts/statuses. Missing Google authorization leaves local data saved and eventually marks synchronization failed; reconnect and use Retry failed. The Library filters by client, publication, reporter and date; displays newest first and exports the filtered data.

## Validation and operating limits

`npm run build`, `npm test`, and `npm run test:coverage` cover existing reporter/media-list/OAuth behavior plus disposable reset fixtures, CSV/XLSX parsing, multiple-file HTTP uploads, exact URLs/row errors, deduplication, destination reuse, write verification failure, retries, pause/cancel, actual server process restarts, Conquest synchronization, a 386-record automatic backfill, exact destination metadata, folder validation, and preservation of all existing upload jobs. Tests use fake Google transport and fixture tokens. Live delivery is reported separately only after actual Google API write/read-back verification.

The persistent local Node server is required for overnight processing. The Vercel serverless deployment intentionally returns 503 for queue operations; no remote coverage backend or migration was introduced. Uploads are limited to 10 MB per file. Run one standalone server per data directory. Keep local state and uploaded files together on durable disk. Large spreadsheets are parsed in memory. File selection/drop transfers the batch automatically, one file at a time to bound memory. Unparseable files and rejected rows remain visible without blocking valid files. Separate delivery state persists retries and resumes interrupted backfills after restart. A terminal delivery failure remains visible and can use Retry failed without another upload; new uploads never reset the local library.
